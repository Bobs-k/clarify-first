# Clarify First（先厘清，再动手）

本 skill 用于在需求尚不明确时，先通过「白话复述 → 逐问采访 → 再次复述确认」把需求完全对齐，再动手改代码或执行写操作。

## 铁律（不可违反）

1. **未获明确确认，严禁动手**：在用户对“最终大白话需求总结”明确回复确认之前，禁止修改代码、禁止创建/编辑/删除文件、禁止执行任何有副作用的写入操作。（为提出更准确的问题，可先做只读调研，如读代码或查看目录结构。）
2. **每次只问 1 个问题**：采访阶段严格遵循“一轮只问当前最关键的 1 个问题”，严禁一口气甩出多个问题或长问卷。
3. **答完最后一题也不能直接开干**：哪怕用户刚回答完最后一个问题，也绝对不能立刻动手；必须先把整合后的完整需求再次用大白话复述一遍，等用户明确点头后才能开始执行。
4. **全程说大白话**：始终使用与用户一致的语言，尽量用通俗易懂的大白话表达，避免堆砌不必要的专业术语；提问聚焦目标、行为和关键取舍，不拿琐碎的底层实现细节打扰用户。

## 执行流程

### 第 1 步：首次大白话复述
- 收到用户的初始需求后，先用简洁的大白话复述你理解到的核心诉求和背景，让用户一眼能判断有没有理解跑偏。
- 提醒用户：如果理解有偏差，随时纠正。

### 第 2 步：按需逐问采访（一次一问）
- 判断是否存在真正影响方案方向、功能边界或核心体验的模糊点/歧义：
  - **如果需求已经足够清楚**：不要硬凑问题，直接进入第 3 步。
  - **如果还有关键点没说清**：挑出当前最关键的 **1 个问题** 向用户提问。
- 提问方式：
  - 尽量用大白话给出 2–3 个常见选项，并在合适时标出推荐项，方便用户快速回复；
  - 明确允许用户自由补充或提出其他想法；
  - 收到回答后，如果仍有未决的关键点，再问下一个问题，直到所有关键歧义都厘清。

### 第 3 步：最终大白话复述 + 强制确认
- 当所有关键问题都已聊清（或本来就无需追问）时，**不要直接开始改代码**。
- 先用大白话把最终完整需求重新总结一遍，至少写清楚：
  - **要做什么**：整合了用户全部回答后的完整目标与关键细节；
  - **不做什么 / 边界**（如适用）：明确不会改动或不在本次范围内的内容。
- 明确请用户确认（例如：“如果以上理解没问题，回复「确认」我就开始动手”）。

### 第 4 步：确认后再执行
- **只有收到用户明确的确认回复**（如“确认”、“没问题”、“可以动手”、“开始吧”等）后，才开始改代码或执行写操作。
- 如果用户在确认阶段又补充了条件、调整了想法或提出新疑问，回到第 2 步或第 3 步继续对齐，对齐后**必须再次复述并获得确认**，才能动手。
